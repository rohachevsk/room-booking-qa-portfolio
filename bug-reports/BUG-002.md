# [BUG-002] Database Seed Script Deletes All Existing Data

**Status:** Open
**Priority:** High
**Severity:** High
**Module:** Database / Seed
**Environment:** Backend / Local Development

## Description

The Prisma seed script unconditionally deletes existing records from multiple database tables before inserting seed data.

The script contains `deleteMany` operations for:

* logs
* bookings
* rooms
* users

No environment check or confirmation is performed before deleting the data.

## Preconditions

1. The backend project is available.
2. The Prisma seed script is available at `prisma/seed.ts`.
3. The database contains existing data.

## Steps to Reproduce

1. Open `prisma/seed.ts`.

2. Inspect the beginning of the seed script.

3. Observe the following operations:

   await prisma.log.deleteMany()
   await prisma.booking.deleteMany()
   await prisma.room.deleteMany()
   await prisma.user.deleteMany()

4. Observe that there is no `NODE_ENV` production guard or explicit confirmation before these operations.

> The seed command was intentionally not executed against a real database. This issue was confirmed through code inspection.

## Expected Result

The seed script should prevent destructive operations against production or other protected environments.

Possible approaches:

* refuse to run when `NODE_ENV=production`;
* use upsert operations instead of deleting existing data;
* require an explicit destructive flag such as `--wipe`.

## Actual Result

Code inspection confirms that running the seed command would execute unconditional `deleteMany` operations against the database before inserting seed data.

## Suggested Fix

Add an environment guard and require explicit confirmation for destructive database resets.

Example:

```
if (process.env.NODE_ENV === 'production') {
  throw new Error('Database seed is disabled in production');
}
```

For destructive resets, use an explicit command or flag such as `--wipe`.
