# [BUG-008] Partially Occupied Hour Appears Available in Calendar

**Status:** Open
**Priority:** Medium
**Severity:** Medium
**Module:** Calendar / Booking Timeline
**Environment:** Frontend / Local Development

## Description

The booking timeline represents availability using hourly cells, but it does not account for bookings that occupy only part of an hour.

As a result, an hour containing an existing partial booking can appear available and allow the user to select an impossible one-hour interval.

The backend correctly detects the conflict and rejects the booking with `409 Conflict`.

## Preconditions

1. Frontend application is running.
2. A room is available for booking.
3. The room already has a booking from `10:30` to `11:00`.

## Steps to Reproduce

1. Open the booking calendar.

2. Find the room with the existing booking from `10:30` to `11:00`.

3. Observe the `10:00` timeline cell.

4. Click the apparently available part of the `10:00` hour.

5. Observe that the booking modal proposes:

   10:00 — 11:00

6. Confirm the booking.

7. Observe the API response.

## Expected Result

The UI should account for partial occupancy.

The user should either:

* be prevented from selecting the occupied interval;
* see the occupied part of the hour visually marked;
* or be offered a valid free interval.

The UI should not suggest an interval that is known to conflict with an existing booking.

## Actual Result

The `10:00` hour appears available even though the room is occupied from `10:30` to `11:00`.

The booking modal proposes:

```
10:00 — 11:00
```

After confirmation, the backend rejects the request with:

```
409 Conflict
```

## Suggested Fix

Update the timeline availability logic to consider existing bookings and their exact start/end times.

Before opening the booking modal, calculate whether the selected interval overlaps an existing booking.

If an overlap exists, disable the conflicting interval or suggest the nearest available time range.
