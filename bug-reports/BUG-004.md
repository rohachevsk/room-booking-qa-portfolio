# [BUG-004] Missing Rate Limiting on Login Endpoint

**Status:** Open
**Priority:** Medium
**Severity:** Medium
**Module:** Security / Authentication
**Environment:** Backend / Local Development

## Description

The authentication endpoint does not implement rate limiting for repeated login attempts.

Multiple failed login requests can be sent consecutively without the server returning `429 Too Many Requests`.

## Preconditions

1. Backend application is running.
2. The `/api/auth/login` endpoint is accessible.

## Steps to Reproduce

1. Send `POST /api/auth/login` with invalid credentials.
2. Repeat the request 20 times within approximately one minute.
3. Observe the HTTP responses.
4. Inspect the backend code for rate-limiting or login-attempt protection.

## Expected Result

After exceeding a defined number of failed attempts, the API should temporarily reject additional requests with:

```
429 Too Many Requests
```

A rate-limiting mechanism should protect authentication endpoints from repeated automated attempts.

## Actual Result

All 20 tested login attempts returned:

```
401 Unauthorized
```

No `429 Too Many Requests` response was observed.

Code inspection also found no implemented rate-limiting, throttling, or login-attempt tracking mechanism.

## Suggested Fix

Implement rate limiting for authentication endpoints such as `/auth/login` and `/auth/register`.

The exact threshold should be defined according to the application's security requirements.
