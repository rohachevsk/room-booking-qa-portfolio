# [BUG-006] Log Records Grow Indefinitely Without Retention or Cleanup

**Status:** Open
**Priority:** Low
**Severity:** Low
**Module:** Database / Logging
**Environment:** Backend / Local Development

## Description

The application writes records to the `logs` table for multiple operations, but no log retention or cleanup mechanism was found.

Code inspection did not identify scheduled deletion, retention logic, or another mechanism for removing old log records.

## Preconditions

1. Backend application is running.
2. Database is available.
3. The application performs operations that generate log records.

## Steps to Reproduce

1. Inspect the backend code for log creation.

2. Observe that operations such as login, registration, booking creation, and cancellation create records in the `logs` table.

3. Search the project for cleanup mechanisms such as:

   cron
   retention
   prune
   setInterval

4. Observe that no log cleanup mechanism is implemented.

5. Inspect the current number of records in the `logs` table.

Example query:

```
SELECT COUNT(*) FROM "logs";
```

6. After two test runs, the table contained:

```
31

records.
```

## Expected Result

The application should have a defined log retention policy.

Old log records should be removed or archived according to the application's operational requirements.

## Actual Result

No automatic log retention or cleanup mechanism was found.

New log records continue to be inserted without an implemented expiration or deletion policy.

## Suggested Fix

Implement a log retention policy.

For example:

* periodically delete logs older than the defined retention period;
* run cleanup as a scheduled background job;
* add an index on `createdAt` to make retention queries efficient.

Example cleanup query:

```
DELETE FROM "logs"
WHERE "createdAt" < NOW() - INTERVAL '12 months';
```

The actual retention period should be determined by the project's operational and compliance requirements.
