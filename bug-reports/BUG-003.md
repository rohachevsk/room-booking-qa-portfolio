# [BUG-003] Invalid UUID in roomId Causes Internal Server Error

**Status:** Open
**Priority:** Medium
**Severity:** Medium
**Module:** Bookings / Input Validation
**Environment:** Backend / Local Development

## Description

The `POST /api/bookings` endpoint does not validate the `roomId` format before passing it to Prisma.

When a non-UUID string is provided as `roomId`, Prisma throws an exception and the API returns an empty `500 Internal Server Error` instead of a client-side validation error.

## Preconditions

1. Backend application is running.
2. A valid authenticated JWT is available.
3. The booking endpoint is accessible.

## Steps to Reproduce

1. Send a `POST` request to:

   /api/bookings

2. Use a valid JWT in the `Authorization` header.

3. Send the following JSON body:

   {
   "roomId": "not-a-uuid",
   "title": "t",
   "startTime": "<tomorrow>T10:00:00.000Z",
   "endTime": "<tomorrow>T11:00:00.000Z"
   }

4. Observe the HTTP response.

## Expected Result

The API should validate the UUID format before accessing the database and return:

```
400 Bad Request
```

with a JSON error message, for example:

```
{
  "message": "Invalid roomId"
}
```

A valid UUID that does not correspond to an existing room should continue to return `404 Not Found`.

## Actual Result

The API returns:

```
500 Internal Server Error
```

The response body is empty because the Prisma exception is not handled as a validation error.

## Suggested Fix

Validate `roomId` before passing it to Prisma.

For example, use UUID validation middleware or a schema validation library and return `400 Bad Request` when the format is invalid.
