# [BUG-005] Registration Accepts a Full Name Containing Only Whitespace

**Status:** Open
**Priority:** Low
**Severity:** Low
**Module:** Authentication / Registration / Input Validation
**Environment:** Backend / Local Development

## Description

The registration endpoint accepts a `fullName` value containing only whitespace characters.

An empty string is rejected correctly, but whitespace-only input bypasses the validation.

## Preconditions

1. Backend application is running.
2. The registration endpoint is accessible.
3. The email address used in the request is not already registered.

## Steps to Reproduce

1. Send a `POST` request to:

   /api/auth/register

2. Use the following JSON body:

   {
   "fullName": "   ",
   "email": "[ws@example.com](mailto:ws@example.com)",
   "password": "secret12"
   }

3. Observe the response.

## Expected Result

The API should reject whitespace-only names with:

```
400 Bad Request
```

The validation should trim the input before checking whether it is empty.

## Actual Result

The API returns:

```
201 Created
```

A user is created with a `fullName` containing only whitespace.

For comparison, an empty string:

```
{
  "fullName": "",
  "email": "ws@example.com",
  "password": "secret12"
}
```

is correctly rejected with `400 Bad Request`.

## Suggested Fix

Trim `fullName` before validation and reject the value if the resulting string is empty.

For example:

```
const fullName = input.fullName.trim();

if (!fullName) {
  return res.status(400).json({
    message: 'Full name is required'
  });
}
```
