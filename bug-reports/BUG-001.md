# [BUG-SEC-001] Insecure JWT Fallback Secret Allows Forged JWT Acceptance

**Status:** Open  
**Priority:** Critical  
**Severity:** Critical  
**Module:** Security / Authorization  
**Environment:** Backend / Local Development  

## Description

The application uses a hardcoded fallback secret (`'local-development-secret'`) when the `JWT_SECRET` environment variable is not provided. Because this secret is predictable, an attacker who knows the fallback value can generate a cryptographically valid JWT. This may allow authentication or authorization bypass if the forged token is accepted by protected endpoints.

## Preconditions

1. Backend server is running.
2. The `JWT_SECRET` environment variable is not provided, causing the application to use the hardcoded fallback secret from `config/env.ts`.

## Steps to Reproduce

1. Generate a forged JWT locally with the payload `{"sub": "fake-id", "role": "ADMIN"}` signed with `'local-development-secret'`.
2. Send a request to a protected endpoint (e.g., `GET /api/bookings/my`) including `Authorization: Bearer <forged_token>`.

## Expected Result

The server should reject the forged JWT and return `401 Unauthorized`.

## Actual Result

The server does not reject the forged JWT, and the request proceeds past JWT verification. The application then fails with an internal exception and returns `500 Internal Server Error`.

## Suggested Fix

Remove the fallback secret in `config/env.ts`. Enforce strict validation on application startup and prevent the server from starting if `JWT_SECRET` is undefined.
